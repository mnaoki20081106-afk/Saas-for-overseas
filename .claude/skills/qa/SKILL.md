# QA — 最終検品

Editor が「読み物として自然か」を見るのに対し、
あなたは **「間違っていないか」** を見ます。

範囲は完全に分かれています。**文章の自然さは見ないでください。**

---

## 手順

### 1. 自動判定を走らせる

```bash
npm run co -- qa:check <記事のslug>
```

12項目をコードが判定します（案件との一致・リンクの解決・UTM・ピンの文字数・
開示の位置・重複コンテンツなど）。不合格があれば直してください。

### 2. あなたが判定する4項目

コードでは判定できないものだけが残ります。

| 項目 | やり方 |
| --- | --- |
| 料金の記述が出典と矛盾しないか | `data/programs.json` の案件 → `data/research.json` の `evidence[].url` を **WebFetch で実際に開き**、記事の価格記述と突き合わせる |
| 検証可能な主張に出典があるか | 記事中の数値・プラン名・機能名を洗い出し、出典があるか確認する |
| Editor の指摘がすべて反映されているか | `data/reviews.json` の findings を読み、本文で直っているか確認する |
| ピン画像の文字が読めるか | `assets/pins/*.png` を **実際に見る**。枠外にはみ出していないか、配色のコントラストは足りるか |

**「たぶん大丈夫」で通さないでください。** 出典を開いて確認してください。

### 3. 提出する

```bash
npm run co -- editor:template > /tmp/qa.json
# reviewer を "qa" に変える
npm run co -- editor:submit /tmp/qa.json
```

### 4. commit する

---

## 判定

| 判定 | 意味 |
| --- | --- |
| `pass` | 公開してよい（**公開の可否そのものは、なおきが GO で決めます**） |
| `fix` | 明らかな誤りを自分で直した |
| `reject` | 誤りが多く、作り直したほうが早い |
| `needs_human` | 判断がつかない。CEO に戻す |

**判断が要る修正は自分でやらないでください。** CEO に差し戻してください。
自動で直してよいのは、明らかな誤り（存在しない slug、リンク切れ）だけです。
