# 案件の調べ方（サラ ★必読）

## この工程の存在理由

**出典のない数値を書かないこと。** これがこの工程の唯一にして最大の目的です。

誤った報酬条件を記事に書くと、アフィリエイト規約違反で **提携を切られます。**
一度切られると、その案件では二度と稼げません。

## 手順

### 1. 前提を読む

```bash
npm run co -- researcher:context
```

いまのフェーズ・足切り条件・既に持っている案件・過去に落とした候補が出ます。
**既に持っている案件は提出しないでください。**

### 2. 候補を探す（WebSearch）

```
"recurring affiliate program" SaaS <カテゴリ>
<製品名> affiliate program commission
site:partnerstack.com <カテゴリ>
"lifetime recurring commission" software affiliate
```

**いきなり有名な製品を狙わないでください。**
大手は審査が厳しく、アフィリエイト記事も飽和しています。
実績ゼロの段階では「審査が通ること」のほうが重要です。

### 3. 一つずつ、実際にページを開く（WebFetch）★ここが本番

**検索結果のスニペットだけで数値を書かないでください。**

| 開くページ | 確認すること |
| --- | --- |
| アフィリエイト/パートナーページ | 報酬モデル・報酬率・Cookie期間・支払い条件・**参加条件** |
| 価格ページ | 一番安い有料プランの月額 |

確認したら、**そのページに書かれていた文をそのまま引用**します。要約ではなく引用です。

```json
"evidence": [{
  "field": "commissionRatePct",
  "url": "https://example.com/affiliates",
  "quote": "Earn 25% recurring commission for the lifetime of the customer."
}]
```

**確認できなかった項目は値を `null` にして `unverified` に項目名を入れます。**
推測で埋めると `co` が受け付けません。それが正しい動作です。

### 4. 英語圏の競合を実際に数える

日本語競合がゼロでも、英語の比較記事が充実していれば SEO では勝てません。

```
"<製品名> vs" review
"<製品名> alternatives"
best <カテゴリ> for small teams
```

| 判定 | 意味 |
| --- | --- |
| `thin` | リスト記事に名前が載っている程度。実際に使った話がない |
| `outdated` | 古い。廃止されたプランや昔の価格を書いている |
| `moderate` | そこそこ充実している |
| `saturated` | 詳しい比較記事が何本もある。勝ちにくい |

**`thin` か `outdated` なら、日本語競合と関係なく狙う価値があります。**

### 5. 審査の通りやすさを見積もる（★初期はここが最重要）

| アフィリエイトページの記載 | 難易度 |
| --- | --- |
| 誰でも参加できる / 即時承認 | 1〜2 |
| PartnerStack / Rewardful / FirstPromoter 経由のフォーム | 2〜4 |
| 「審査があります」とだけ書いてある | 4〜6 |
| 「月間◯◯PV以上」などの条件がある | 7〜9 |
| 「確立されたメディアのみ」「招待制」 | 9〜10 |

**どれだけ報酬が高くても、承認されなければ収益はゼロです。**

### 6. Pinterest との相性

| 相性 | 商材 |
| --- | --- |
| 高い（7〜10） | デザイン・サイト作成・プロジェクト管理・請求書・SNS管理 |
| 低い（1〜4） | バックエンド・開発者向けAPI・セキュリティ監査 |

画面・数字・ビフォーアフターで説明できるものほど向いています。

### 7. 提出

```bash
npm run co -- researcher:template > /tmp/research.json
# 編集する
npm run co -- researcher:submit /tmp/research.json
```

形が違えば、どこがどう違うかが表示されます。直して同じコマンドを実行してください。
落ちた候補も理由つきで記録されるので、次回また調べる無駄がなくなります。

## 足切り条件（フェーズで変わる）

いまは **bootstrap**（提携ゼロ〜4件）。審査の通りやすさを重視します。

| 項目 | bootstrap | growth（承認5件以上） |
| --- | --- | --- |
| 報酬モデル | recurring / hybrid のみ | 同じ |
| 月額報酬 | $15 以上 | $30 以上 |
| 平均継続 | 8ヶ月以上 | 10ヶ月以上 |
| 想定LTV | **$150 以上** | **$300 以上** |
| 日本語競合 | 5/10 以下 | 3/10 以下 |
| 審査の難しさ | **6/10 以下** | 8/10 以下 |

## よくある間違い

| 間違い | なぜダメか |
| --- | --- |
| 検索結果のスニペットから報酬率を書く | 古い情報のことが多い。必ずページを開く |
| 「たぶん30%くらい」と推測で書く | 誤った報酬条件は提携解除の理由になる |
| 一度きりの報酬の案件を出す | 積み上がらない。このモデルに合わない |
| 有名な大手ばかり出す | 審査が厳しく、記事も飽和している |
| 日本語競合だけ見る | 英語で書くので、英語の競合が本当の相手 |

## 上限

1回の調査は **10件まで**。**週2回まで**。
在庫を増やしても、応募して承認をもらうのはオーナーの手作業なので、詰まるだけです。
