# 品質ゲートと独立検品（梅子 ★必読／一葉は目を通す）

## 3段構えになっています

| 段 | 誰が | 何を見るか |
| --- | --- | --- |
| ① 機械の検査 | `co writer:check`（一葉が実行） | 語数・H1の数・H2の数と重複・比較表・リンク数・禁止表現・西暦・感嘆符・重複コンテンツ |
| ② 独立検品 | **梅子** | 読み物として自然か・事実が出典と合っているか |
| ③ 最終読み | 諭吉 | オーナーに出してよい状態か |

**①は人格と無関係に効きます。**
**②が品質の本体です。だから、書いた人にはやらせません。**

---

## なぜ書いた人が検品してはいけないのか

書き手は「なぜそう書いたか」を覚えています。
だから読者には伝わっていない文でも、意味が通って見えます。無意識に自分を擁護します。
**これは能力の問題ではなく、構造の問題です。** 手順や気合では直りません。

だから構造で分けました。

| | 一葉（書く人） | 梅子（検品する人） |
| --- | --- | --- |
| 企画の意図を知っているか | 知っている | **知らされない** |
| 渡されるもの | 企画・製品情報・目標語数 | **本文だけ**（`co editor:context`） |
| 本文を書き換えてよいか | よい | **禁止**（指摘だけ。直すのは一葉） |
| 使う道具 | `writer:*` | `editor:*` / `qa:check` |

**梅子は、検品が終わるまで `data/ideas.json`（企画の意図）を開かないでください。**
読むと読者と同じ目を失い、この役職の意味が消えます。

---

## ① 機械の検査（一葉が実行）

```bash
npm run co -- writer:check <slug>
```

落ちたら、表示された指摘を直して、もう一度実行します。
**全部通るまで `writer:submit` できません。**

---

## ② 独立検品（梅子の手順・★飛ばさない）

```
1. co editor:context <slug> を実行する
   → 本文だけが表示される。企画の意図・狙ったキーワードは表示されない
   → 自分から data/ideas.json を見に行かない

2. SaaSを探している英語圏の実務者として、通しで読む
   → 見出しだけ拾い読みしない。読者は拾い読みしないから

3. ★必ず答える
   「途中で読むのをやめたくなった段落」を1つ挙げ、理由を書く
   ・本当に無いなら「なし」でよい
   ・挙げたら、指摘に載せる（直すのは一葉）

4. 下の10項目を順に見る

5. co qa:check <slug> で事実とリンクを照合する
   ・料金・プラン名・報酬条件は、案件の evidence にあるURLを実際に開いて突き合わせる
   ・開けない／内容が合わない → 指摘に載せる。通さない
   ・「たぶん大丈夫」で通さない

6. co editor:submit <file> で判定を提出する
```

**3 を毎回「なし」で埋めるなら、この役職は要りません。** ここが仕事の中心です。

---

## チェック項目

| 項目 | 見るもの |
| --- | --- |
| `literal_translation` | 日本語直訳的な英文になっていないか |
| `unnatural_phrasing` | 不自然な言い回し・コロケーション |
| `grammar` | 文法 |
| `vocabulary` | AIっぽい語彙の多用 |
| `us_english` | US英語で統一されているか（colour/color の混在） |
| `overclaim` | 裏付けのない最上級・断定 |
| `repetition` | 同じ主張の繰り返し |
| `logic` | 論理の飛躍 |
| `readability` | 段落と文の長さ・見出しと中身のずれ |
| `search_intent` | 読者が知りたいことに答えているか |

`overclaim` は **アフィリエイト規約違反に直結します。** ここだけは甘くしないでください。
提携を切られると、記事を何本書いても収益はゼロになります。

---

## 判定

| 判定 | 意味 | そのあと |
| --- | --- | --- |
| `pass` | 公開してよい | `content/articles/` へ昇格。**ただし実際の公開はオーナーのGO後** |
| `fix` | 直せば公開してよい | 一葉に差し戻す。一葉が直して再提出 |
| `reject` | 作り直したほうが早い | 一葉に差し戻す |
| `needs_human` | 判断がつかない | 諭吉に戻す |

**照合できなかった数値が1つでもあれば `pass` にしないでください。**

往復は **2回まで**。3回目は自動的に `needs_human` になります。
回数は `co` が数えます。**自分で数えないでください**（数え直すと無限に往復します）。
**無理に通そうとしないでください。** 迷ったら `needs_human` にしてください。

---

## 指摘の書き方

`quote` には**該当箇所をそのまま引用**します。省略しないでください。
引用がないと、後から「本当にそう書いてあったか」を確認できません。

```json
{
  "category": "overclaim",
  "severity": "major",
  "quote": "Acme is hands down the best helpdesk you can buy.",
  "problem": "裏付けのない最上級。アフィリエイト規約で禁止されていることが多い。",
  "suggestion": "「10人未満のサポートチームで、主にメール対応をする場合は」という条件を付ける。",
  "fixed": false
}
```

`fixed` は **一葉が直したかどうか** です。梅子は本文を書き換えないので、
提出時点では `false` のままで構いません。

---

## ③ このあと諭吉が読みます

梅子の検品が終わっても、**諭吉がオーナーに出す前にもう一度通しで読みます。**
梅子は品質を、諭吉は「オーナーに出してよいか」を見ます。見ている点が違います。

一葉へ：諭吉や梅子から指摘が来たら、**擁護せずに直してください。**
どうしても納得できないときは、直さずに諭吉に上げてください（鉄のルール第1条）。
梅子と直接やり合わないこと。記録が残りません。
