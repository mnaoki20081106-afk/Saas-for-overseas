# コストを下げる（と、下げてはいけないところ）

## 1. いまいくらかかるか

`config/config.json` の `models.profile` で3段階から選べます。既定は `balanced`。

| profile | 案件リサーチ | 記事の設計 | 記事本文 | ピン文案 | 記事1本あたりの目安 | 月30本 |
| --- | --- | --- | --- | --- | --- | --- |
| `quality` | Opus 5 | Opus 5 | Opus 5 | Opus 5 | 約 $0.60 | 約 $22 |
| `balanced`（既定） | Opus 5 | Sonnet 5 | **Opus 5** | Haiku 4.5 | 約 $0.40 | 約 $14 |
| `budget` | Sonnet 5 | Haiku 4.5 | Sonnet 5 | Haiku 4.5 | 約 $0.16 | 約 $6 |

（案件リサーチは週1回で、上記とは別に1回あたり $0.5〜1.5 程度）

**変え方**：`config/config.json`

```json
"models": { "profile": "budget" }
```

環境変数 `CLAUDE_MODEL` を設定すると、全工程がそのモデルで上書きされます（テスト用）。

実行するとトークン数と概算コストが工程ごとに出るので、実測で調整してください。

```
✓ 本文執筆: ... — in 5,120 / out 11,430 tok ≈ $0.311
```

## 2. どこを削ってよくて、どこを削ってはいけないか

**削ってよい**

- ピン文案（`pins`）— 10枚ぶんの短い文を作るだけ。Haiku で十分です
- 記事の設計（`brief`）— 構成を出すだけ。Sonnet で落ちません
- 応募文・発信素材（`growth`）— 頻度が低く、人間が目を通します

**削ると効くのが目に見えて落ちる**

- **記事本文（`article`）** — ここがこの事業の商品そのものです。
  Sonnet に落とすと、指定語数を下回りやすくなり、品質ゲートの書き直しが増え、
  結果として**安くならないことがあります**。まず `balanced` で1本出して、
  出力を読んでから判断してください
- **案件リサーチ（`research`）** — Web 検索の結果を突き合わせて
  「継続報酬か」「本当に継続10ヶ月もつか」を判断する工程です。
  ここを間違えると、その後の記事とピンが全部無駄になります

## 3. すでに効いている節約

- **プロンプトキャッシュ** — system プロンプトに `cache_control` を付けてあるので、
  同じ工程を繰り返すぶんの入力コストが下がります
- **記事の再生成をしない** — 品質ゲートに落ちても、まるごと書き直すのではなく
  「欠陥リストを渡して直させる」ので、2回目が安く済みます
- **ピン画像は API を使わない** — HTML/CSS を Chromium で撮っているので、
  1枚あたり **$0** です。画像生成 API を使うと、ここだけで月 $50〜150 かかります
- **本数を減らす** — `config/config.json` の `content.articlesPerRun` を
  `1` から下げる／`autopilot-daily` の cron を隔日にする

## 4. 公式以外のエンドポイントを使う場合

「無料クレジット」「格安 Claude API」を謳うサービスを使う前に、**必ず**これを実行してください。

```bash
ANTHROPIC_BASE_URL=https://その事業者のエンドポイント \
ANTHROPIC_API_KEY=そこで発行された鍵 \
npm run autopilot provider:check
```

このパイプラインが必要とする機能を1つずつ実測し、**足りないものがあれば
どの工程が壊れるかまで**表示します。所要30秒、コストは $0.05 未満です。

判定される項目：

| 機能 | 無いとどうなるか |
| --- | --- |
| 基本のメッセージ送受信 | 何も動きません |
| ストリーミング | 記事本文がタイムアウトします |
| **構造化出力**（`output_config.format`） | 案件のJSON化・記事の設計・ピン文案・応募文が全部止まります |
| **サーバーサイド Web 検索** | 案件リサーチが丸ごとできません（このプロジェクトの入口です） |
| adaptive thinking / effort | 記事の質が落ちます（動きはします） |
| プロンプトキャッシュ | 割高になります（動きはします） |

素の `/v1/messages` だけを実装した互換エンドポイントは珍しくありません。
その場合、**構造化出力と Web 検索が落ちて、パイプラインの半分が使えなくなります。**

### 技術的に通っても、確認すべきこと

`provider:check` が全部緑でも、次は機械では判定できません。

1. **プロンプトと記事の元ネタは、全部その事業者のサーバーを通ります。**
   何を保存し、学習に使うかは規約次第です
2. **Anthropic の正規のリセラーか。** プールされた鍵を又貸ししている場合、
   その大元のアカウントが止まった瞬間に、予告なく全部止まります
3. **止まったとき何日で戻せるか。** 毎日走る自動化の土台にするなら、
   ここが答えられない先は土台になりません
4. **応答が名乗るモデルと、実際のモデルが一致しているか。**
   `provider:check` は要求したモデルと応答が名乗るモデルを突き合わせて警告を出しますが、
   名乗り自体を偽られたら検出できません。**記事の質が落ちても気づけない**のが一番厄介です

### 現実的な落としどころ

- **本番（毎日走る自動化）は公式のキーで回す。** 月 $6〜22 です
- 試したいなら、**まず `provider:check` を通す**。落ちた項目があれば、その時点で見送り
- 全部通ったとしても、**書かせるのは検証用の記事だけ**にして、
  公式で書いた記事と読み比べてから本番に入れるか決める

初期費用を抑えたいなら、**まず `models.profile` を `budget` にしてください。**
月 $6 なら、素性の分からないエンドポイントに全プロンプトを流すリスクを取る理由がありません。
