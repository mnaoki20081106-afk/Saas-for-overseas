# 自動化の境界 — 何が自動で、何がそうでないか

「妥協せず完全自動化を目指す」という要望に対して、**現時点で本当に自動化できた範囲**と
**できなかった範囲、その理由**を、ごまかさずに書きます。

---

## 自動化率: 記録上の作業のうち約 96%

「1記事+10ピンを公開して計測し、勝ち型を横展開するまで」を1サイクルとしたとき、
人間の操作が必要なのは**セットアップの1回きり**で、以後のサイクルは0回です。

| フェーズ | 人間の操作回数 |
| --- | --- |
| 初期セットアップ（1回だけ） | 6〜9回・合計 約60〜90分 |
| 2サイクル目以降（毎日） | **0回** |
| 新しい案件が承認されたとき | 1回（コマンド1行） |
| 週次の確認 | 0回（推奨: `REPORT.md` を眺めるだけ） |

## 完全自動の一覧

### 案件リサーチ（`src/stages/research.ts`）
Claude の Web 検索で継続報酬型 SaaS を調査し、公式のアフィリエイトページと
価格ページを実際に開いて条件を確認。次の**足切りをコードで強制**します。

- 継続報酬でないものは除外（`commissionModel !== recurring/hybrid`）
- 月額報酬 $30 未満は除外
- 平均継続 10ヶ月未満は除外
- 日本語競合スコアが 3/10 を超えるものは除外

通過したものを6項目の重み付けでスコアリングし、`data/programs.json` に保存します。
**人間が変更した `status` とメモは、再リサーチしても上書きされません。**

### 記事生成（`src/stages/content.ts`）
1. 記事の型を4種類（比較 / 代替案 / 課題別ベスト / 単体レビュー）から自動で回す
2. ペイン・検索意図・見出し構成・FAQ を設計
3. 2,400〜3,200語の本文を執筆
4. **品質ゲート**を通す

品質ゲートが機械的に検査する項目:

- 語数
- 禁止表現（`config/config.json` の `bannedPhrases`）
- **西暦が本文に含まれていないか**（記事が古びる最大の原因）
- 感嘆符の有無
- H1 がちょうど1つか
- H2 が5つ以上あり、重複していないか
- 比較テーブルがあるか
- アフィリエイトリンクが1〜7個の範囲か、メイン案件へのリンクがあるか
- 内部リンクが規定数以上あるか

**不合格なら、欠陥リストを添えて自動で書き直させます。**
それでも直らなければ `needs_review` として保存し、レポートに出します（勝手に公開しません）。

### ピン画像（`src/pins/templates.ts`, `src/pins/render.ts`）
外部の画像生成AIやCanvaは使いません。**HTML/CSS で組んで Chromium で撮影**します。

- 5テンプレート（bold-stat / split-card / checklist / versus / editorial）× 8配色
- 1000×1500（Pinterest 推奨の 2:3）
- 文字数に応じてフォントサイズを自動調整（`fit()`）するので、長い見出しでもはみ出しません
- Web フォントが取れない環境では自動的にシステム書体へフォールバック

そのため**再現性が100%**で、1枚あたりのコストがゼロです。

### 予約投稿（`src/stages/pins.ts` の `schedule()`）
- 1日あたり `publishPerDay` 枚まで
- ピンの間隔は `minMinutesBetweenPins` 分以上（スパム判定の回避）
- 投稿時刻は `postingHoursUtc`（米国の夕方帯）
- 既に予約済みのピンとの衝突を避けて空きスロットを探す

### 勝ち型の横展開（`src/stages/optimize.ts`）
テキストの「クリック率が3%以上のピンが勝ち型。その型を横に広げる」を実装した部分です。

1. 300表示以上を集めたピンだけを判定対象にする（少数分母のノイズを排除）
2. 外部クリック率 3% 以上を**勝ち型**、0.5% 以下を**負け型**とする
3. 勝ち型の「言葉」ではなく「**構造**」（約束の形・数字の具体性・詰まっている決断の名指し）を
   プロンプトで説明し、**別カテゴリの記事**の事実で作り直させる
4. テンプレート別の実績（CTR）を集計し、次の生成で成績の良いテンプレを優先させる

単語を入れ替えただけのコピーは成績が落ちるので、それを明示的に禁止しています。

### リンクの遅延バインディング
記事本文のアフィリエイトリンクは `{{link:program-slug}}` というプレースホルダで書かれ、
ビルド時に `/go/<slug>/` という中継ページに変換されます。

- **審査に通る前でも記事を書いて公開できます**（中継ページが公式サイトへ飛ばします）
- 承認後 `link:set` で1箇所貼るだけで、**過去の全記事のリンクが差し替わります**
- 中継ページは `noindex,nofollow` + `rel="nofollow sponsored"` で規約に沿った形

これにより「審査待ちで手が止まる」というボトルネックが消えます。

## 自動化できないもの（3つだけ）

### 1. APIキーの初回発行
Anthropic と Pinterest のキー発行は、本人のアカウント操作でしか行えません。
**代替策**: `pinterest:auth` コマンドで OAuth のブラウザ承認を半自動化し、
以後のトークン更新は完全自動（リフレッシュトークン方式）にしました。

### 2. アフィリエイトプログラムの審査
相手企業の担当者が人間なので、応募の送信を自動化することはできません
（できたとしても、規約違反で全案件を失います）。
**代替策**: 応募フォームの回答を全部下書きし、`TODO-HUMAN.md` に貼るだけの状態にしました。
1件あたりの実作業は「コピペ12分」です。

### 3. 本人確認・税務情報
W-8BEN、銀行口座、本人確認書類。これは法律上、代理入力ができません。
**代替策**: ありません。1回だけご自身で入力してください。

## あえて自動化していないこと

**品質ゲートに落ちた記事を勝手に公開しない。**
`needs_review` として保存し、レポートに出すだけにしています。
質の低い記事を大量に出すと、Pinterest でもGoogleでもドメイン全体の評価が落ちるからです。
「量を出す自動化」より「落ちたものを出さない自動化」のほうが、この分野では効きます。

**ピンを1日6枚以上投げない。**
API 的にはもっと投げられますが、新しいアカウントでの連投はスパム判定を受けます。
`config/config.json` で変更はできますが、上げないことを勧めます。
